# 阅读时长统计

设置 → 阅读显示今日、近七个自然日（含今日）与累计阅读时长，按设备本地日期统计，显示精确到分钟。上线前的阅读时间不回填。

正文已加载、阅读窗口可见并聚焦时计时；切到后台、窗口失焦、离开阅读页或正文尚未就绪时暂停。阅读菜单仍属于阅读页。后台听书不计入阅读时长。计时使用单调时钟；超过五秒的计时器间隔视为设备挂起，不计入。每十五秒及暂停、离页时保存，异常终止最多可能丢失尚未保存的一段时间。

Rust 通过 `readerx_reading_time_get` / `readerx_reading_time_add` 串行读取与累加，保存在应用数据目录 `state/readerx.readingTime.json`，写入临时文件后替换。格式为 `schemaVersion: 2`，`contributions` 保存各来源的 `days`（本地日期到毫秒数）与 `books`（跨设备书籍 uid 到毫秒数）累计值，顶层 `days` / `books` 是它们求和的显示视图。旧安装缺少文件时自动从零开始；不修改书籍与阅读进度。删除书籍或重置阅读进度不会清除历史统计。阅读时长参与现有局域网同步。

## 同步与迁移

各设备的新增时长归入本机独立来源，标识保存在应用数据目录 `reading-time-origin`，不进入备份或同步。同步发布 `reading_time` 不可变快照，身份由来源、统计项与累计值共同派生；合并时对每个来源的每个统计项取最大值，再将各来源相加。因此重复同步、乱序传输、经第三台设备转发和旧快照重发都不会重复计数或覆盖较新时长。两台设备同时阅读的时间会相加，不按墙钟时间去重。

版本 1 的历史统计首次读取时迁移为独立来源并保存，以后不会再次迁移；已有书籍记录换成跨设备 uid。旧格式不含来源信息，若同一份版本 1 数据已经复制到多台设备，再各自迁移，就无法辨认它们是否是相同历史。版本 2 备份保留来源，恢复到新设备后新增时间另记。

同步落地通知前端重载统计，设置页无需重新打开。首次启用同步与启动对账会发布已有记录；关闭网络同步后的阅读仍在本地累计，重新启用后一起同步。阅读时长不随书籍删除级联清除。不同客户端需升级后才能显示同步来的时长。

浏览器开发模式仅保存于内存，不写 WebView 持久化存储。
