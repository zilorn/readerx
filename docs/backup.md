# 数据备份与恢复（导入 / 导出）

> 状态：**已接入 App**（设置 → 数据 → 数据备份）。本文件说明备份里有什么、归档长什么样、
> 导入的两种语义，以及与「局域网同步」的边界。

目标：把**整台设备**的数据变成一个文件，换机 / 重装 / 归档备查时再搬回来。
与同步（`docs/sync.md`）的分工是清楚的：

| | 局域网同步（`readerx-sync`） | 数据备份（本文件） |
| --- | --- | --- |
| 解决什么 | 两台设备各自离线改数据，联网后**自动合并** | 把整台设备的数据**搬到一个文件** |
| 搬什么 | 元信息 / 正文 / 进度 / 书签 / 目录 / 分组 / 书源 / 规则（封面与插图不搬） | 整台设备的用户数据：正文、封面、插图、书签、书源、规则全在里面 |
| 触发方式 | 开着就自动跑 | 用户显式导出 / 导入 |
| 冲突 | 字段级合并 + 冲突队列 | 不做冲突裁决：合并（补齐 / 同 id 覆盖 / 集合取并集）或覆盖恢复 |

要连封面与插图一起换机用**备份**；两台设备长期并行使用用**同步**。

---

## 1. 归档格式

一个备份就是一个 **zip 文件**（后缀 `.zip`）。内部路径与应用数据目录一一对应，
所以用户可以自己解开来看、也可以按目录结构手工抢救某本书：

```text
readerx-backup.json          清单：格式版本、导出版本、时间、是否含登录信息、各类条目数
state/<key>.json             readerx.* 状态（书架进度、分组、书源分组、替换 / 分章规则、偏好…）
books/<id>/bookdetail.json   书籍元信息（书名 / 作者 / 封面 / 分组归属…）
books/<id>/content.json      章节正文
books/<id>/bookmarks.json    书签
images/<name>                章节插图 / PDF 页面图（文件名前缀就是它所属的书籍 id）
book_sources/<id>.json       书源定义
source_sessions/<id>.json    书源登录态（**仅当导出时勾选「包含登录信息」**）
```

清单里的 `format` 是 `readerx-backup/1`：读到**更高**的版本直接报错，而不是按旧语义读坏新数据。

**不在归档里**（刻意排除）：

| 目录 | 为什么 |
| --- | --- |
| `sync/` | 设备身份、配对码、操作日志 —— 跟着设备走；搬过去等于制造两台同 id 的设备 |
| `tts-audio/` | 听书缓存，能从正文重新生成 |
| `logs/` | 应用日志 |

正文与插图都以**字节流**写进归档（不解析、不在内存里再复制一份），因此导出的内存占用与
书库体积无关；正文用 deflate 压缩，插图（JPEG / PNG）本来就是压缩格式，直接存储（stored），
不再白烧 CPU 重压一遍。

### 1.1 凭据

书源登录态（Cookie）与 WebDAV 密码属于凭据，**默认不导出**：

- 不勾选时，`source_sessions/` 整个不写；`state/readerx.webdavServers.json` 里的 `password`
  抹成空串（服务器地址与用户名不是凭据，留着对恢复有用）；
- 勾选后原样写入，界面与本文档都提醒「这份文件里有账号登录信息」；
- 日志里永远只有数量，没有内容（与全项目口径一致）。

## 2. 导入的两种语义

导入前先选文件、看预览（只读清单，不解压正文），再选：

### 2.1 合并（默认）

**不删本机任何数据**，只补齐与对齐：

| 数据 | 合并规则 |
| --- | --- |
| 书籍 | 本机有同一个 id → 覆盖；本机有**同一本书**（跨设备身份相同、id 不同）→ 不重复导入，只把归档的书签并进去；否则新增 |
| 书签 | 按书签 id 取并集（与同步同一口径），`bookId` 改写成落点那本书的本机 id |
| 阅读进度（`readerx.shelf`） | 按书籍 id 取并集，同一本书取 `updatedAt` 较新的一方 |
| 分组（书架 / 书源） | 以**分组名**为身份：本机已有同名分组就用本机 id，否则沿用归档 id（被占用时另起一个新 id） |
| 书源 | 同 id → 覆盖；同一站点（地址归一后相同）→ 保留本机那份；否则新增 |
| 文本替换 / 分章规则 | 以规则内容为身份取并集（与同步的表一致） |
| 插图 | 同名即同一张（名字里带来源地址哈希），已存在就跳过 |
| 偏好类状态（主题 / 字号 / 并发…） | 本机没有才写入；本机有则保持本机（导入别人的备份不该改掉自己的设置） |

### 2.2 覆盖恢复

「回到备份那一刻」：先写归档里的数据，再把归档里没有的本地书与书源删掉
（连同它们的书签、插图、听书缓存与登录态）；内容类状态文件（书架 / 分组 / 书源分组 /
替换规则 / 分章规则）与归档完全一致，**归档里没有的那一项会被清空**；偏好类状态被归档覆盖。

顺序是**先写后删**：中途失败 / 断电时最坏是「本机多出几本已有的书」，
而不是「书删了一半、备份还没写进去」。删除操作需要对号入座（本机多出来的才有），
界面上是「再点一次确认覆盖」的二次确认。

### 2.3 跨设备身份（同一本书怎么认出来）

书的本机 id 是**每台设备各自生成**的，直接按 id 对齐会把整库变成双份。因此合并模式按
**同步的同一套身份**认书（`src/sync/identity.rs`）：

- 在线书：书源地址 + 书籍详情页地址；
- 导入书：文件名（大小写归一）+ 字节数。

算的是**归档那一侧自己的**书源地址（从归档里的书源定义查），否则跨设备对不上。
身份相同的书不重复导入，归档里的进度 / 书签 / 按书生效的替换规则改写到本机那本书上。

覆盖恢复不做身份对齐：本机那份最终会被删掉重建，id 保持不变。

## 3. 平台与文件选择器

- **桌面**：系统保存 / 打开对话框给的是普通路径，`std::fs` 直接读写；
- **Android**：SAF 给的是 `content://` 地址（`ACTION_CREATE_DOCUMENT` / `ACTION_GET_CONTENT`），
  普通文件 API 打不开，走 `tauri-plugin-fs` 的移动端实现拿文件描述符
  （`Fs::open` 内部处理 `content://`）。

除这一层差异，压缩 / 解压逻辑两端完全一致（`src-tauri/src/data_transfer/archive.rs`）。
原生对话框必须在主线程上弹，因此命令层先弹框拿路径，再把磁盘 I/O 交给
`commands::blocking`（与 `readerx_pick_book_file` 同一口径）。

---

## 4. 与同步的相互作用

导入是**绕过命令层直接批量写文件**的：书 / 书源 / 进度 / 书签都不会逐条触发本地写钩子。
因此：

- 导入结束后调一次 `SyncService::on_data_imported()` —— 同步启用过就做一次全量对账
  （把导入的内容发布进引擎），否则导入的东西在下次同步前对其它设备不可见；
- 覆盖恢复删除本地书 / 书源**之前**调用同步的删除钩子（删除要读 `bookdetail.json` 定位身份），
  让引擎里留下墓碑，避免对端一改那本书就把它「复活」回本机；
- 同步从未启用过（没有引擎）时这些都是空操作。

## 5. 代码位置

```text
src-tauri/src/data_transfer/
  mod.rs        口径、归档常量、清单与结果类型（含「条目名必须安全」的校验）
  archive.rs    zip 封装、清单读写、条目名分类、目标 / 来源文件句柄（含 Android content://）
  export.rs     采集本地数据 → 写归档（含凭据过滤、进度回调）
  plan.rs       导入的规划：认书 / 认分组、算 id 换算表（只读，不写盘）
  import.rs     读归档 → 合并 / 覆盖写回（书籍 / 插图 / 书源 / 登录态 / 状态，先写后删）
  merge.rs      状态文件的合并规则（纯函数 + 单测）
  commands.rs   readerx_data_export / readerx_data_import_pick / readerx_data_import
  round_trip.rs 端到端回归（真实磁盘布局 + 真实 zip，只把窗口换成 mock）
src/lib/backup.ts               前端接线：调命令、进度、导入后按依赖顺序重载缓存
src/pages/DataBackup.tsx        设置 → 数据 → 数据备份
```

验证：

```text
cargo test --offline --lib data_transfer     # 合并规则 + 归档往返 + 凭据开关
cargo test --offline -p readerx              # 全量（含同步回归，确认钩子没被破坏）
pnpm exec tsc --noEmit && pnpm run i18n:check
```

已知取舍：

- **不做增量**：每次导出都是全量（含正文），大书库的文件会很大；
- **不加密**：归档不加密（勾选登录信息时里面就有 Cookie）；需要更强保护应自行加密存档；
- **合并按 id / 身份对齐，不做字段级裁决**：同一本书两边都改了元信息时，合并模式以归档那份为准
  （同 id）或保留本机（同身份），差异不会进冲突队列（要字段级裁决用同步）；
- **旧布局书籍**（`books/<id>.json`）导出时已在读取路径上迁移过；归档里若出现这种条目，导入会
  跳过并记一条日志，而不是半懂地写。
