# 书源图片正文（漫画 / 扫描 / 图文混排）

阅读器支持「正文 = 图片」的章节（整章图片）以及「文字中嵌插图」的图文混排。
书源作者**不需要新增能力开关、不用改 schemaVersion**，只需让 `bookContent` 把图片表达出来即可。
图片地址解析、防盗链请求、阅读时下载与本地缓存全部由阅读器自动完成。

## 1. 如何表达图片

### 方式 A：返回含 `<img>` 的 HTML（推荐，与老协议兼容）

`bookContent` 照旧返回字符串。纯文本时的行为与旧版**完全一致**；一旦返回的 HTML 里出现
`<img>`，阅读器会按出现顺序抽取图片，并把图片前后的文字一起保留：

```js
async function bookContent(chapter, book) {
  const resp = await http.get(chapter.chapterUrl, { headers: { Referer: book.bookUrl } });
  const el = html.query(resp.body, "div#comic-img"); // 漫画：图片列表容器
  if (!el) throw new Error("找不到图片容器");
  return el.html; // <img src="https://img.xx/1.webp"><img src=".../2.webp">…
}
```

图文混排同样适用：文字段落与 `<img>` 交错出现即可，段落与图片会按顺序连成一章内容。

- 图片地址取 `src`；站内懒加载常见写法也兼容：`data-src` / `data-original` /
  `original` / `data-lazy-src` / `lazy-src` / `data-url` / `data-echo`（按上述顺序逐个尝试）。
- 相对地址（`/imgs/1.jpg`、`../x.png`）按**正文页地址**（`chapterUrl`）自动解析为绝对地址。
- `script` / `style` / 注释内部出现的 `<img` 不会误识别；没有可用地址的 `<img>` 会被当作不存在。
- 解析不了的内容（对象里没有 `text` / `images` 键）仍按普通文本返回，保持旧行为。

### 方式 B：返回对象 `{ text?, images? }`

需要显式表达“这一章是一组图”时，可直接返回对象（`images` 也可写作 `imgs`）：

```js
async function bookContent(chapter, book) {
  // …从分页接口收集到本章所有图
  return { text: "本章说明文字（可省略）", images: ["https://img.xx/1.webp", "…2.webp"] };
}
```

- `text`：可选，会作为普通正文段落（放在图片前）。
- `images` / `imgs`：图片地址数组（字符串），相对地址同样按 `chapterUrl` 解析。

## 2. 图片怎么被下载与存储

**拉正文时不下载图片**：`bookContent` 只解析出图片地址，正文会立刻落盘，章节读取速度与纯文字章一致。
图片在**用户读到这一章时**逐张下载（先按图片地址请求，图片未就绪时正文显示占位）；
窗口内已下载章节的图片会在正文取完后顺手预取（见下面「阅读窗口图片预取」）：

- 请求走**该书源的 HTTP 会话**：自动携带书源的默认请求头、User-Agent 与已保存的
  Cookie（含网页登录捕获的 Cookie）。
- 每张图的 `Referer` 自动取**正文页地址**（`chapterUrl`）——绝大多数防盗链图站校验的正是
  阅读页同域 Referer，因此无需书源额外配置。
- 下载成功的图片随即落成本地文件并**把引用写回本章本地缓存**：离线可读、本次运行内反复翻页
  不重复请求，下次打开这本书也不再重新下载。图片字节存在应用数据目录的 `images/` 下
  （`<bookId>_<图片地址哈希>.<扩展名>`），章节里只留文件名（`local` 字段）——
  书籍 JSON 的体积与图片总量解耦，图片也不会经 IPC / WebView 的 JS 字符串搬运，
  因此「一章几百张图」不会再因为 base64 副本堆积把应用撑崩。
- 渲染时由应用内自定义协议 `readerx-img` 直接从文件读取（Android 上即
  `http://readerx-img.localhost/…`）；排版需要的图片尺寸由 Rust 读**文件头**给出，
  WebView 不再为了量尺寸把整章图片解码一遍，正文里的图片也按 `loading="lazy"` 惰性解码。
- 图片只是「还没下载」时显示转圈占位；**下载失败**（或被清理掉的本地副本读不出来）的占位框
  带「重试」按钮（在占位文字右边），点一下立即重取；同一张图再次读到本章时也会自动再试一次，
  两次自动尝试之间有冷却，不会连环打图站。
- **阅读窗口图片预取**：正文按「当前章 ±5 章」预取，这一圈章节的**正文都取回之后**，
  阅读器会顺手把窗口内**已下载章节**里还没取过的图片也取回来 —— 顺着往下读时，图片通常
  已经在本地。预取失败即放弃（不在后台反复重试，也不计入章节失败），用户读到该章时再取一次。
- 「下载全部正文」把**正文与图片分两趟**跑：先下完所有章节正文，再单独过一遍图片；
  下载中的进度会分别显示。

> 因此请尽量让 `chapterUrl` 就是**实际出现图片的页面地址**；若某站要求 Referer 为首页等
> 其它地址，可在章节规则里用 `http.get` 自行换取图片直链，并在默认请求头中配好 Referer。

## 3. 整章图片章节

当一章只由图片组成（没有可读文字）时：

- 阅读器把它当作普通一章展示：分页/滚动模式会像排版一张张插图那样排这些图。
- 图片不计入章节字符（字数统计 / 阅读进度按“章”计），与 EPUB 里的插图口径一致。
- 正文（图片地址列表）取回后本章即视为已就绪；某一章所有图片都没下下来时，本章正文照常可读，
  页面上是带「重试」的占位框，而不是整章失败。

## 4. 兼容性与注意事项

- **老书源零改动**：`bookContent` 返回纯文本的写法与旧版本行为完全一致。
- **已缓存章节不受影响**：之前按纯文本缓存的章节照常阅读；旧版缓存进章节的 data URL 图片
  会在**打开这本书时自动迁移**成图片文件（只留引用），迁移失败（畸形数据 / 磁盘错误）
  则原样保留、图片照旧可用。
- **数据格式向后兼容**：书源 `schemaVersion` 仍为 1；在线书的图片块有可选字段 `remote`
  （图片原始网络地址，用于阅读时下载 / 重试）与 `local`（本地副本文件名），
  旧版客户端忽略 `local` 即可，新版读旧版书库也不会崩（旧数据按旧字段渲染）。
- 图片以文件形式存放于应用数据目录的 `images/`（不在书籍 JSON 内）：**删除书籍会一并清理**
  该书的图片文件；「下载全部正文」把整本书的图都下载到本地时，请预估磁盘占用。
- 单张图上限 24 MiB、单次请求超时 60 秒；图片下载的并发与全局「书源并发」设置一致
  （最多 4 路并行）。

## 5. 常见问题

| 现象 | 排查 |
| --- | --- |
| 图片显示“图片缺失”占位框 | 该图下载失败（无网 / 超限 / 非图片响应）。可点占位文字右边的「重试」；仍失败时先确认 `chapterUrl` 可访问；图站防盗链的 Referer 域名与章节页不一致时，可在规则里先用 `http.get` 换到可直链的地址。 |
| 整章都是占位框 | 本章图片都没下载成功：检查网络 / Cookie 是否过期（网页登录重新登录），或逐张点「重试」。 |
| 图片一直转圈不出图 | 图片正在下载（图片多 / 网络慢）。等待或翻到别处再回来；若一直不出，多为图站限速或地址失效。 |
| 后台还在悄悄下图 | 阅读窗口（当前章 ±5 章）的正文取完后会预取这一圈章节的图片；在「下载正文」面板里点「停止下载」即可停下。 |
| 占位框上没有「重试」按钮 | 该图的地址已丢失（旧版本下载失败时只留下空地址），没有可重试的目标：用阅读设置里的「重新加载本章」重取本章正文与图片。 |
| 返回的是 JSON 站点接口 | 老写法 `JSON.parse(...).join("\n\n")` 仍可用；需要带图时改用方式 B 返回 `{ text, images }`。 |
